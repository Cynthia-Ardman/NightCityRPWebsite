Yeah, I would **not** put all of that as separate left-nav items. That would turn the site into a junk drawer fast.

The cleanest structure is:

**Directory → Guidebook**

Then inside **Guidebook**, have sections/cards like:

* Getting Started
* FAQ
* Rules & Restrictions
* Schedule & Events
* Systems
* Character Creation Help
* VRChat / Discord Setup
* NPC Acting

That way “Directory” becomes the place for reference material, while “Personal” stays for stuff tied to the user’s account: dashboard, characters, ledger, requests, missions, etc.

I’d call it **Guidebook** instead of “Info” or “FAQ” because it can contain onboarding, rules, systems, schedules, and reference docs without sounding too narrow.

# Guidebook / Info Directory System Change List

## 1. Add Guidebook Under Directory

Add a new **Guidebook** section under the left-side **Directory** navigation.

This should be the main home for NCRP reference material, onboarding information, rules, systems explanations, schedules, FAQ content, and setup guides.

**Navigation placement**

* Directory

  * Lore
  * Guidebook

**Acceptance criteria**

* Guidebook appears under Directory, not under Personal.

## 7. Guidebook Editing Permissions

Guidebook content should be editable by authorized staff.

### Admins

Admins can edit and publish Guidebook content directly.

### Fixers

Fixers can submit edits, but those edits should require approval before going live.

Fixer edits should go to Pending Requests.

**Acceptance criteria**

* Admins can edit Guidebook pages directly.
* Fixer edits create pending approval requests.
* Approved edits update the Guidebook.
* Denied edits do not publish.
* Guidebook edits are audit logged.

---

## 8. Pending Request Integration

Fixer-submitted Guidebook edits should go into Pending Requests.

Recommended tab:

* Lore / Guidebook

* Lore

**Pending request should show**

* Page/section affected
* Submitted by
* Before/after changes
* Submitter notes
* Approve button
* Deny button

**Acceptance criteria**

* Guidebook edits are reviewable before publishing.
* Pending edit buttons are clearly labeled.
* Approval publishes the change.
* Denial rejects the change.
* Actions are audit logged.

## 11. Sync / Re-Import Behavior

Store the original Discord source ID for each imported Guidebook page.

This allows future re-imports or manual refreshes.

**Acceptance criteria**

* Each imported page stores its source Discord ID.
* Admins can see where imported content came from.
* Re-importing can update existing pages instead of creating duplicates.
* Re-import conflicts should require review before overwriting edited website content.

## 12. Audit Logging

Audit log these actions:

* Guidebook page imported
* Guidebook page created
* Guidebook page edited
* Guidebook edit submitted
* Guidebook edit approved
* Guidebook edit denied
* Guidebook page deleted
* Guidebook page re-imported/refreshed
* Guidebook source changed
* New user banner dismissed, optional

**Acceptance criteria**

* Guidebook changes are traceable.
* Import errors are logged.
* Staff can see who changed what and when.

I’d avoid naming the tab “FAQ” because it’s too narrow. **Guidebook** is broad enough to hold rules, setup, systems, and onboarding without making the nav feel bloated.
